# Primitive DB

Это учебный проект простой базы данных на Python.
Программа позволяет создавать и удалять таблицы, просматривать их структуру, добавлять, читать, изменять и удалять записи.
Структура таблиц и их содержимое сохраняются в JSON-файлах, поэтому данные не теряются после завершения программы.

## Запуск проекта

Проект использует `uv` для управления окружением и зависимостями.

Для установки зависимостей выполните:

`uv sync`

После этого запустите базу данных:

`uv run database`

## Управление таблицами

После запуска программа ожидает ввода команд.

**create_table** <имя_таблицы> <столбец1:тип> ... — создать таблицу
**list_tables** — показать список всех таблиц
**drop_table** <имя_таблицы> — удалить таблицу
**exit** — выйти из программы
**help** — справочная информация

### Создание таблицы

Для создания таблицы используется команда:

`create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ...`

Например:

`create_table users name:str age:int is_active:bool`

Программа автоматически добавляет столбец `ID:int` в начало таблицы, если пользователь его не указал.

Поддерживаются три типа данных: `int`, `str`, `bool`.

Пример результата:

`Таблица "users" успешно создана: со столбцами: ID:int, name:str, age:int, is_active:bool`

### Просмотр таблиц

Чтобы посмотреть список созданных таблиц, используется команда:

`list_tables`

Пример результата:

- users

### Информация о таблице

Для просмотра структуры таблицы используется команда:

`info users`

Команда выводит названия столбцов и их типы с помощью библиотеки `PrettyTable`.

### Удаление таблицы

Для удаления таблицы со всеми данными используется команда:

`drop_table <имя_таблицы>`

Например:

`drop_table users`

Пример результата:

`Таблица "users" успешно удалена`

### Справка

Команда `help` выводит список доступных команд.

### Выход из программы 

Команда `exit` завершает работу приложения.

## CRUD-операции

CRUD — основные операции работы с данными:

- **insert** — создание записи.
- **select** — чтение записей.
- **update** — изменение записей.
- **delete** — удаление записей.

### INSERT — добавление записи

Синтаксис:

`insert into <имя_таблицы> values (<значение1>, <значение2>, ...)`

Пример:

`insert into users values ("Sergei", 28, true)`

Программа проверяет количество значений и их типы. Значение `ID` генерируется автоматически.

Пример результата:

`Запись с ID=1 успешно добавлена в таблицу "users".`

### SELECT — просмотр записей

Вывести все записи:

`select from users`

Вывести записи по условию:

`select from users where age = 28`

Результат отображается в виде таблицы с помощью библиотеки `PrettyTable`.

### UPDATE — изменение записей

Синтаксис:

`update <имя_таблицы> set <столбец> = <новое_значение> where <столбец> = <значение>`

Пример:

`update users set age = 29 where name = "Sergei"`

Программа находит записи по условию `WHERE`, проверяет тип нового значения и обновляет указанный столбец.

Изменение столбца `ID` запрещено.

### DELETE — удаление записей

Синтаксис:

`delete from <имя_таблицы> where <столбец> = <значение>`

Пример:

`delete from users where ID = 1`

Программа удаляет все записи, соответствующие условию `WHERE`, и сохраняет обновлённые данные.

## Декораторы и кэширование

В проекте используются декораторы для обработки ошибок, подтверждения операций и измерения времени выполнения функций.

### Обработка ошибок

Декоратор `handle_db_errors` обрабатывает исключения `FileNotFoundError`, `KeyError`, `ValueError` и другие ошибки во время выполнения операций базы данных. При возникновении ошибки программа выводит сообщение.

### Подтверждение удаления

Декоратор `confirm_action` запрашивает подтверждение перед командами `delete` и `drop_table`.

Например:

`drop_table a`

Программа выводит запрос:

`Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]:`

Ответ `y` / `yes `подтверждает удаление, а `n` / `no` отменяет операцию.

### Измерение времени

Декоратор `log_time` измеряет длительность выполнения функций `insert` и `select` с помощью `time.monotonic()`.

Пример сообщения:

`Функция select выполнилась за 0.000 секунд`

### Кэширование запросов

Функция `create_cacher()` использует замыкание и словарь для сохранения результатов `select`.

При повторном одинаковом запросе результат берётся из кэша, поэтому таблица не загружается и фильтрация не выполняется повторно. После успешного `insert`, `update`, `delete`, `create_table` или `drop_table` кэш очищается, чтобы данные оставались актуальными.

## Структура проекта

- `main.py` — точка входа.
- `engine.py` — обработка команд.
- `core.py` — операции с таблицами и записями.
- `utils.py` — чтение и сохранение JSON-файлов.
- `parser.py` — разбор передоваемых значений.
- `decorators.py` — декораторы и кэширование.
- `constants.py` — константы.

## Хранение данных

Метаданные таблиц хранятся в файле:

`db_meta.json`

Для каждой таблицы записи сохраняются в отдельном JSON-файле:

`data/<имя_таблицы>.json`

Например:

`data/users.json`

При отсутствии файла данных функция `load_table_data()` возвращает пустой список.

При добавлении, изменении или удалении записей данные сохраняются в JSON.

При выполнении `drop_table` соответствующий файл данных удаляется физически.
